# Deliberately NOT pinned to an exact patch version (e.g. torch==2.2.2):
# hosting platforms (Streamlit Community Cloud included) periodically bump
# their default Python version out from under you, and PyTorch only builds
# wheels for a given Python ABI some time after that Python's release — an
# exact old pin then has *no* matching wheel and the deploy fails outright.
# A flexible lower bound lets pip pick whatever CPU build actually exists
# for the interpreter in use. The CPU index above + PEP 440 local-version
# precedence (X.Y.Z+cpu sorts above plain X.Y.Z) means pip still prefers
# the CPU-only build over a much larger CUDA-bundled default when both
# exist for the same version. Checkpoints here are plain state_dicts, which
# load fine across this version range (verified against torch 2.8/numpy 2).
